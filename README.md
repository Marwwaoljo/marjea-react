# مَرْجِع — نسخة النقل المحلية

هذه نسخة عمل مستقلة عن الأرشيف الأصلي. لا تعدّل ملفات المشروع الأصلي عند العمل هنا.

## المتطلبات

- Node.js 22.16 أو أحدث
- npm 10.9 أو أحدث
- PostgreSQL مخصص لبيئة التطوير، منفصل تماماً عن قاعدة الإنتاج
- مفاتيح Clerk وFirebase الحالية وفق إعدادات المشروع
- مفتاح OpenAI API عند تفعيل التحليل الدلالي
- مفتاح Resend وعنوان مرسل موثّق لإرسال دعوات الأعضاء
- Google Cloud Storage وإعداد Application Default Credentials لمستندات تراخيص الجهات

## الإعداد المحلي

1. افتح هذا المجلد في VS Code.
2. انسخ `.env.example` إلى `.env`.
3. أدخل إعدادات التطوير ومفاتيح الخدمات في `.env` فقط. لا تضع المفاتيح في ملفات الواجهة ولا ترفع `.env` إلى Git.
4. نفّذ:

   ```bash
   npm install
   ```

5. نفّذ فحوصات الأنواع:

   ```bash
   npm run typecheck
   ```

6. اختبارات الوحدات التي لا تتطلب قاعدة بيانات:

   ```bash
   npm run test:unit
   ```

7. بناء واجهة وخادم النسخة الحالية:

   ```bash
   npm run build
   ```

## إعداد الخدمات المباشرة

### OpenAI

- ضع المفتاح في `OPENAI_API_KEY` على الخادم فقط.
- لا تضف `VITE_OPENAI_API_KEY` أو أي متغير يعرّض المفتاح للمتصفح.
- بقي نموذج التحليل `gpt-5.4-mini` وإعدادات Chat Completions والتحقق من المخرجات وسياسة المحاولات والمراجعة البشرية دون تغيير مقصود.

### Resend

- ضع المفتاح في `RESEND_API_KEY`.
- ضع عنوان المرسل الموثق في `MARJEA_RESEND_FROM`.
- يرسل الخادم دعوات الأعضاء مباشرة إلى واجهة Resend، مع مفتاح idempotency لمنع تكرار الإرسال عند إعادة الطلب.

### Google Cloud Storage

- اضبط `PRIVATE_OBJECT_DIR` بصيغة `/اسم-الحاوية/المسار-الاختياري`.
- عيّن `GOOGLE_APPLICATION_CREDENTIALS` إلى مسار ملف حساب خدمة مخصص للتطبيق، أو جهّز Workload Identity في بيئة الاستضافة.
- امنح الحساب أقل الصلاحيات اللازمة على الحاوية الخاصة، ولا تستخدم حساباً شخصياً أو صلاحيات مالك المشروع.

## حالة التحويل

اكتملت في هذه المرحلة إزالة تكاملات منصة الاستضافة السابقة من موفّر OpenAI والبريد وتخزين مستندات التراخيص وإعدادات الحزم. كما حُوّلت مساحة العمل إلى npm.

**لم يكتمل بعد تحويل واجهة React إلى HTML/CSS/JavaScript مستقل.** ما زالت واجهة React الحالية موجودة داخل هذه النسخة مؤقتاً حتى تتم عملية التحويل صفحةً صفحةً مع المحافظة على التصميم والسلوك. كذلك لم تُشغّل اختبارات التكامل أو أي ترحيلات لقاعدة البيانات في هذه المرحلة.

لا تشغّل migrations على قاعدة بيانات أصلية أو إنتاجية. اختبر دائماً على قاعدة تطوير مستقلة.

## الواجهة المستقلة HTML/CSS/JavaScript

بدأ نقل الواجهة إلى تطبيق Vanilla مستقل في `web/` دون React:

```bash
npm run dev:web
```

الواجهة تعمل على `http://127.0.0.1:5173`، وتحوّل طلبات `/api` إلى خادم API المحلي على المنفذ `8080` عند تشغيله منفصلاً:

```bash
npm run dev:api
```

لبناء ملفات الواجهة الثابتة فقط:

```bash
npm run build:web
```

**حالة النقل:** تم إنشاء هيكل Vanilla مستقل، ونقل أصول الصور والخطوط، وإعداد التنقل الأساسي والصفحة الرئيسية وبعض مسارات الصفحات. لم يكتمل بعد تحويل تدفقات Clerk، ولوحات الجهات والأفراد، وإدارة الأعضاء والحالات، ونماذج التسجيل والتكاملات التفاعلية. ملفات React الأصلية ما زالت محفوظة في `artifacts/marjea/` كمرجع ولا تُستخدم من تطبيق `web/`.

**قيود هذه المرحلة:** بناء الواجهة لا يشغّل اختبارات التكامل ولا فحص TypeScript ولا أي migration أو اتصال تغييري بقاعدة البيانات. لا تضع مفاتيح الخدمات السرية في ملفات `web/`؛ تبقى على الخادم فقط.

في إعداد npm الحالي، لم تعد حزمة واجهة React القديمة ضمن workspaces النشطة؛ بقيت ملفاتها في `artifacts/marjea/` كمرجع للتحويل ومقارنة الصفحات، بينما workspaces النشطة تقتصر على خادم API والمكتبات التي يحتاجها. أمر `npm run build` يبني خادم API والواجهة Vanilla ولا يشغّل فحص TypeScript تلقائياً. أمر `npm run typecheck` موجود كأمر مستقل عند طلب تشغيله.
